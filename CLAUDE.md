# nectar-apple

nectar's native Apple clients, in a fork of Swiftfin: **Nectar TV** (tvOS), the **Swift iPhone app**, and the **iPad shell** (Tauri 2 around nectar's own web client). Bee's Roadhouse side; owned by Ocelli. The server, its API and the web client are Forage's, in `bees-roadhouse/nectar`.

> The house rules (merge authority, the one-`main` flow, brand, secrets) are in `~/.claude-shared/ROADHOUSE.md` and the DevOps book (Branching Strategy, Pull Request & Code Review Process). This file is only what is particular to this repo. Dates mark when a rule was decided, so the next reader knows it was deliberate.

## What is ours and what is upstream's

- **Ours:** `Nectar/` (the TV app, the iPhone app, `NectarKit`, the stub server, the fork's tests), `iPad/`, `.github/workflows/nectar-tv.yml` and `ipad.yml`, and this file.
- **Upstream Swiftfin's:** everything else (`Swiftfin/`, `Swiftfin tvOS/`, `Shared/`, `Translations/`, upstream's workflows). The `upstream` remote is `jellyfin/Swiftfin`. Keep changes there to the few that Nectar needs (for example `SubtitleRenditionMatcher`), say in the PR whether each could go upstream, and merge upstream through a PR as a merge commit (#2, 2026-10-16).
- The language is the repo's: Swift and SwiftUI. The iPad shell's Rust and web view is the one exception (#127, 2026-10-21).
- The decision that Nectar is a new app on nectar's own API, reusing Swiftfin's player and UI pieces, is on #14 (2026-10-17). Sign-in is the device flow only.

## Targets

| Target | Where | Build and check |
|---|---|---|
| NectarKit (shared models, API client, sign-in, player core) | `Nectar/NectarKit` | `swift test --package-path Nectar/NectarKit`. It runs on macOS, so no simulator is needed. |
| Nectar TV (tvOS 26+) and its Top Shelf extension | `Nectar/Nectar.xcodeproj`, scheme `NectarTV` | `xcodebuild build -project Nectar/Nectar.xcodeproj -scheme NectarTV -destination 'generic/platform=tvOS Simulator' CODE_SIGNING_ALLOWED=NO` |
| Nectar iPhone (iOS 26+, also iPad-capable) | `Nectar/iPhone/NectarPhone.xcodeproj`, scheme `Nectar` | The same with `-destination 'generic/platform=iOS Simulator'`. The project is generated by `xcodegen generate` from `project.yml` in that folder; both files are committed, so regenerate and commit them together. |
| iPad shell | `iPad/` (Rust in `iPad/src-tauri`, the launch page in `iPad/`) | `cargo test --lib` in `iPad/src-tauri`. Its iOS build is checked on the MacBook's simulator. |
| Fork tests (Swiftfin glue) | `Nectar/SwiftfinForkTests` | `swift test` in that folder. |

The TV app's models are compiled into the iPhone target (`project.yml` lists them), so a change to one is built for both.

## Signing and devices

- **Free personal team** `B5SARBZDRT` for now (no paid membership; Nate enrols as an individual only when he wants TestFlight, 2026-10-16). Its profiles last exactly 7 days, so each device install is re-signed weekly; the last signing date lives on Tasks — Ocelli.
- CI builds are unsigned (`CODE_SIGNING_ALLOWED=NO`). A device build adds `-allowProvisioningUpdates CODE_SIGN_STYLE=Automatic DEVELOPMENT_TEAM=B5SARBZDRT` and installs with `xcrun devicectl device install app`. A re-sign has to move the cached profile aside first, or Xcode reuses it.
- The bedroom Apple TV ("Master Bedroom TV (2)") may be asleep; a launch then fails with "System is asleep". Wake it by hand, and check the server's playback sessions are 0 before a test play. Test launches set `NECTAR_TEST_RUN=1`.
- Debug hooks (autoplay, progress, simulator input) stay uncommitted, saved under `~/ai-workspace/ocelli/hooks/`.

## Tests that prove they ran

- `swift test` prints `Test run with N tests`; compare N with main's, so a harness that silently found nothing shows.
- A test that guards a bug fails when the guard is removed. Break it once on purpose and watch it fail before trusting it (2026-10-26, the lifetime tests on #75 and #122).
- State what was not run (a device, a screen, a runner) in the PR's Evidence. A tvOS or iOS build proves it compiles, and a screen or a device proves it behaves.

## Feel and review

- **Capping reviews every UI change for feel** (pixels from the TV or a simulator run, otherwise from source). The brand standard is KB page 2451, and colours are the role names, never copied hex values.
- **A PR written on Sonnet is merged only after Palp's two-axis review on Opus** (Standards: this file, the house file and the DevOps book; Spec: the issue it closes), posted on the PR and written as separate axes (2026-10-24).
- Ocelli merges its own PRs once they are green and reviewed, with a squash and no admin override. The gate is the repo's CI. Merge without `--delete-branch`, then delete the remote branch with the API once the PR reads MERGED.
- A reviewer's fix goes in its own commit, never inside a "Merge main" commit.

## Working here

- One issue, one branch off `main` (`feature/`, `improvement/`, `refactor/`, `bug/` plus a slug), one worktree under `~/github/bees-roadhouse/.worktrees/nectar-apple/<slug>`, one PR that closes the issue. The main checkout stays on `main`.
- Commits read `<area>: <what, and why>` and are authored `Ocelli <nate@bierlysmith.com>`; the body carries the why. Pushes go through the vault-minted GitHub App helper over https; leave `GH_TOKEN` unset, and leave the remote on https.
- Server needs (an endpoint, a field, a fix in how an item is shaped) go to Forage as a nectar issue with the request and response; when client and server disagree, say which side is wrong.
- Anything that touches the MacBook's setup, the runners or brh-infra goes to Hamulus. Builds on the Mac wait for Hamulus's word when they are heavy.

## Never in a commit

Tokens (access, refresh, the device-flow code), Apple ID credentials, signing certificates, provisioning profiles, the nectar test user's password, DerivedData, `xcuserdata`, debug-hook patches, and titles or names from the household's library. Muzzle a tool that prints a secret.
